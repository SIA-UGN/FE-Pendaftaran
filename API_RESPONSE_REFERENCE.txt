================================================================================
🔐 AUTHENTICATION STRUCTURE
================================================================================

All protected endpoints require Bearer Token (Sanctum):

Header:
Authorization: Bearer {token}

Alternative (via middleware api.token.query):
?token={token}

Token Format:
{id}|{plainTextToken}
Example: 1|abcdefghijklmnopqrstuvwxyz123456789

================================================================================
10. COMMON ERROR RESPONSES
================================================================================

--------------------------------------------------------------------------------
401 Unauthenticated
--------------------------------------------------------------------------------
Description: Token missing, invalid, or expired
HTTP Status: 401

Response:
{
  "message": "Unauthenticated."
}

Causes:
- No Authorization header
- Invalid token format
- Expired token
- Token revoked (after logout)

Solution:
- Login again to get new token
- Check Authorization header format: "Bearer {token}"

--------------------------------------------------------------------------------
403 Forbidden
--------------------------------------------------------------------------------
Description: Authenticated but not authorized for this resource
HTTP Status: 403

Response:
{
  "success": false,
  "message": "Unauthorized access"
}

Or:
{
  "success": false,
  "message": "Hanya admin yang dapat mengakses resource ini"
}

Causes:
- Wrong role (e.g., pendaftar accessing admin endpoint)
- Not owner of resource
- Account not active

Solution:
- Check user role
- Verify resource ownership
- Contact admin if account inactive

--------------------------------------------------------------------------------
404 Not Found
--------------------------------------------------------------------------------
Description: Resource not found
HTTP Status: 404

Response:
{
  "success": false,
  "message": "Resource tidak ditemukan"
}

Or specific message:
{
  "success": false,
  "message": "Profil tidak ditemukan"
}

Causes:
- Invalid ID in URL parameter
- Resource deleted
- Resource never existed

Solution:
- Verify ID parameter
- Check if resource exists
- Use search/list endpoint first

--------------------------------------------------------------------------------
422 Validation Error
--------------------------------------------------------------------------------
Description: Request data validation failed
HTTP Status: 422

Response:
{
  "message": "The given data was invalid.",
  "errors": {
    "email": [
      "The email field is required.",
      "The email must be a valid email address.",
      "The email has already been taken."
    ],
    "password": [
      "The password must be at least 8 characters.",
      "The password confirmation does not match."
    ],
    "nik": [
      "The nik must be 16 characters."
    ]
  }
}

Causes:
- Missing required fields
- Invalid format (email, phone, etc.)
- Field constraints violation (length, type, etc.)
- Unique constraint violation

Solution:

Authentication & Token Management
--------------------------------------------------------------------------------

Token Type: Sanctum Bearer Token
Token Format: {id}|{plainTextToken}
Example: 1|abcdefghijklmnopqrstuvwxyz123456789

Header Format:
Authorization: Bearer {token}

Alternative (via middleware api.token.query):
Query parameter: ?token={token}

Token Storage (Frontend):
- localStorage key: "access_token" (NOT "token")
- Storage format: Plain string, no JSON
- Clear on logout

Example:
```javascript
// Store token after login
localStorage.setItem("access_token", response.data.data.token);

// Retrieve token
const token = localStorage.getItem("access_token");

// Clear on logout
localStorage.removeItem("access_token");
localStorage.removeItem("user");
```

Token Lifecycle:
- Created on: /api/register, /api/login
- Used for: All protected endpoints
- Invalidated on: /api/logout
- No expiration: Tokens don't expire (until logout)

Axios Configuration:
```javascript
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("access_token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

Error Handling Best Practices
--------------------------------------------------------------------------------

Frontend Pattern:
```javascript
try {
  const response = await apiCall();
  toast.success(response.data.message);
  return response.data.data;
} catch (error) {
  if (error.response) {
    // Server responded with error
    const status = error.response.status;
    const message = error.response.data.message;
    
    switch(status) {
      case 401:
        // Unauthenticated - redirect to login
        localStorage.removeItem('access_token');
        router.push('/login');
        break;
      case 403:
        toast.error('Anda tidak memiliki akses');
        break;
      case 422:
        // Validation errors - show field errors
        const errors = error.response.data.errors;
        Object.values(errors).flat().forEach(err => toast.error(err));
        break;
      case 404:
        toast.error('Data tidak ditemukan');
        break;
      default:
        toast.error(message || 'Terjadi kesalahan');
    }
  } else if (error.request) {
    // Request made but no response
    toast.error('Tidak dapat terhubung ke server');
  } else {
    // Something else happened
    toast.error('Terjadi kesalahan');
  }
  throw error;
}
```

Backend Pattern:
```php
try {
    // Business logic
    return response()->json([
        'success' => true,
        'message' => 'Operation successful',
        'data' => $data
    ], 200);
} catch (\Exception $e) {
    return response()->json([
        'success' => false,
        'message' => 'Operation failed',
        'error' => $e->getMessage() // Only in dev
    ], 500);
}
```

Security Considerations
--------------------------------------------------------------------------------

1. Authentication:
   - Always send token in Authorization header
   - Never expose token in URL (except via ?token= for downloads)
   - Clear tokens on logout
   - Validate token on every request

2. File Uploads:
   - Validate file type and size server-side
   - Sanitize filenames
   - Store files outside public directory
   - Serve files via controller (authorization check)

3. Input Validation:
   - Always validate on server-side (Laravel Requests)
   - Client-side validation for UX only
   - Sanitize user input
   - Use parameterized queries (Eloquent ORM)

4. CSRF Protection:
   - Disabled for API routes (Sanctum token auth)
   - Use CSRF tokens for web routes only

5. Rate Limiting:
   - Applied to sensitive endpoints (login, register)
   - Default: 60 requests per minute
   - Returns 429 Too Many Requests if exceeded
